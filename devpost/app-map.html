SplitSeek, mapped

A take-home guide to where things live in the finished proof of concept.

What it is

SplitSeek searches a folder of LOG footage by plain-language description. It pulls one frame every 2 seconds from each clip, asks Jev a yes/no question about each frame ("Does this frame show: a waterfall?"), and ranks the matching stretches. Clicking a result plays the original clip from the matched moment.

It's a Tauri 2 app in two halves:

  • The window, src/: plain HTML, CSS, and JavaScript. It shows the folder picker, progress, search box, results, and video preview.
  • The engine, src-tauri/src/: Rust. It reads folders, runs ffmpeg, calls Jev, ranks results, and serves video. The window asks it to do things through commands.

One action, end to end: searching

src/main.js, search for async function runSearch

Where the Search button lands. It stops any playing preview, then calls the engine with invoke("search", { phrase }). When the answer comes back, renderResults draws the rows, "Show more", and the empty states. A counter (searchId) ignores a slow search if you've already started a newer one.

2

src-tauri/src/lib.rs, search for async fn search(

The engine's side of that call. It creates the Jev client on the first search (so a missing key gives a plain message), runs the search over the prepared frames, then attaches each row's LOG thumbnail. If Jev rejects the key, it drops the client so the next search re-reads .env.

3

src-tauri/src/search.rs, search for fn group(

Turns hundreds of frame scores into a short list. Back-to-back frames of the same clip on the same side of the cutoff become one stretch (e.g. 0:04–0:26 · best 0:12). Then rank sorts the stretches and splits them at CUTOFF. The tests at the bottom of the file show the rules with small examples.

A practice to reuse

When the real environment disagrees, instrument it instead of guessing

What happened. The video preview passed every check in a browser test, then showed a black picture with audio in the real app window. Several causes were plausible: 10-bit HEVC not drawing, seeking failing, or file access breaking. Instead of trying fixes one by one, the build added temporary diagnostics that logged what the video player and the file response actually reported. One click in the real window produced the answer: the clip was labelled text/html instead of video/mp4. Tauri's source confirmed it only recognises a lowercase mp4 extension, and the cameras write .MP4.

The evidence. devpost/checklist.md under Revisions; the fix in src-tauri/src/clip_protocol.rs, whose tests pin the case-insensitive file type and byte ranges; and a second diagnostic run showing playback starting at the best moments (2.00 s and 64.00 s). The diagnostics were removed before committing.

Reusing it. When an agent's checks pass but the real thing misbehaves, ask for a small, temporary probe that records what the system actually sees, run it once in the real environment, and fix what the evidence points to. A test that pins the cause keeps it fixed. The same habit caught a squashed window header in this build: an unexplained 5 px offset in test screenshots that had been written off as a rendering quirk.
